Orion-81

Orion-81 is a space combat game with six degrees of freedom: you move and turn freely along every axis. You pilot a single heavy ship and point its nose with the mouse. The pace is unhurried, yet the controls answer at once: every input takes effect from the next 8 millisecond step, and a big ship simply takes longer to come round.

It has a purpose beyond play. Its revenue is meant to help support software engineers and graphic designers whose work has been affected by artificial intelligence.

In development. Built so far: the rules core (M2), the demo's rules (M2.1), ships as machines (M2.2, done on 26 October 2026) the engine-neutral first-flight layer (M3a, done on 28 October 2026) and game modes, balance and sub-system combat (M2.3, done on 31 October 2026). Air, orbit and descent (M2.4) is being built, and work has started on M4a, the engine-neutral half of M4; nothing of it is merged yet.

What the game will be

The first goal is the clean v0 demo: a small but complete slice of the game. It is planned to hold:

  • eight original ship hulls, each designed for Orion-81;
  • two weapons: lasers, and rockets fired in salvos;
  • waves of drones to fight, in an asteroid arena laid out from a seed, so the same seed gives the same arena;
  • the heads-up display that shows what the pilot needs to know;
  • a packaged build that runs on its own.

The demo counts as finished only when its acceptance tests and the clean-room checks pass, and Andrius has played it and accepted how it feels.

In Orion-81 a ship is a machine made of parts, not a bar of health. Damage to its edges knocks out engines, turrets and sensors one by one; only a hit to the core destroys it. Each weapon has its own job, and a pilot who manoeuvres well beats the automatic mounts.

How the estimate is made

The totals are at the top of this page. The estimate is measured from the work so far: each engine-free milestone is judged from what the same kind of work has already cost. The engine milestones have no measured basis yet, so they are judged by size and their range is wider.

What exists today

The rules core, written in C++. It covers flight; the five weapon families (lasers, rotary cannons, rockets, railguns and point defence); turrets and automatic mounts; damage that travels through each ship's graph of modules; and the world step, which can record a replay and take a fingerprint of the game state, so the same inputs always give the same result. On top of it sit the demo's rules: the sides, respawns, pickups and score, single-player waves, drones and computer pilots, and four difficulty levels. Ships are machines now: damage spreads from part to part, damage control can stop it, a pilot can aim at a ship's subsystems, wrecks break into tumbling debris that can be salvaged, and engines, shields and weapon mounts are power modules. Without any game engine, the presentation layer (M3a) adds cameras, the lens, input, the session, the host and a replay tool. Since 31 October the main line also holds M2.3: game modes, balance and sub-system combat.

The rules give identical results when built with two different compilers. They are checked by 1396 automated tests, and a further 239 test the presentation layer. Each of the two test programs runs in under one second.

There is nothing to play or watch yet. The first playable build is M4.

How it is made

  • Orion-81 is directed by Andrius Bubliauskas with AI. Claude Code by Anthropic writes the code, plans the work and reviews it; Andrius makes the decisions.
  • Five written specs are the source of truth: flight, the fleet, weapons, game modes and the places. They hold the behaviour, the numbers and the acceptance tests.
  • It is a clean restart. The proof of concept began on an open-source base released under the GPL, and a licence review of that prototype found code in it derived from the base. To start again with no licensing issues, development restarted from a clean slate on 14 October 2026, with new specifications written from the game's design and new code throughout. Orion-81 shares no code with the proof of concept.
  • Work sessions are recorded on video as a devlog.
  • Before a milestone starts, its plan is checked against the work before it. When it closes, independent reviews and copy scans look for outside code; the milestone closes so far found none.
  • Third-party code in the game uses permissive licences only, apart from the game engine and the Windows C++ runtime.

Every test

Each automated test checks one rule of the specs against its numbers. A test's name reads "spec reference: what it checks", so a test marked weapons 8.5 checks section 8.5 of the weapons spec. Search for any word, or choose one of the 27 areas.
